# I59 native proxy log / DOM reconciliation

Prepared offline helper only. It neither starts a server nor requests the application nor operates a browser. The original 15 proxy logic tests are a separate preparation level. The tests in this directory use synthetic timeline/DOM data and never become native evidence.

Run only after parent has completed captures and supplied the explicit `NATIVE_READY` manifest:

```sh
/Users/zhouzhenghang/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node /private/tmp/ohri-i59-native-live-replay/replay.mjs /private/tmp/ohri-i59-native-live-replay/native-manifest.json /private/tmp/ohri-i59-native-live-replay/actual-replay-receipt.json
```

The manifest uses `schemaVersion:1`, `status:"NATIVE_READY"`, `logPath`, and `phases`. Each phase requires `id`, `kind`, `windowUTC:[beforeUTC,afterUTC]`, `ownerEvidence`, `configPath`, `requests:[{requestId,role}]`, and `captures:[{path,state,windowUTC,afterDeadline?}]`. Cancellation phases also require `action:{windowUTC,evidence}`. Roles are exactly `pair` or `single_feature`. One ID cannot own both roles. Source URLs never establish an owner by themselves. Native action and request initiator/isolated mount records establish ownership.

Kinds: `abort_pair`, `abort_outer`, `switch_profile`, `feature_cancel`, `error_sibling`, `wrong_chunk`, `pass_retry`, `single_chunk`. Cancellation phases correspond respectively to pair close, outer RNA close, non-CHOL profile switch, and closing both while first feature is pending. A feature switch that launches a new tuple needs a distinct native phase; do not label an old tuple's cancellation as full RNA closure.

`feature_replaced` handles the actual first-feature update separately: old owned pair requests remain canceled before their deadlines; `replacement_tuple_held` checks the explicitly changed first/second tuple, and postdeadline `replacement_single_ready_pair_closed` binds the retained new single feature to its distinct replacement ID, configuration, original response and exact source-profile key. It does not claim RNA closure.

`replacement_pair_ready` is permitted only after a native profile switch or failed sibling phase, when the actual later capture shows an explicit fresh current pair rather than remaining closed/failed. It requires `replacementPairRequestIds`, `replacementConfigPath`, `replacementOpenEvidencePath` and `profileIdAfter`; switched views also retain `profileIdBefore`. The new requests must start after the original recorded replacement action, finish before the native capture, use normal original bodies and have their own distinct declared owner phase. Every old delayed request is still independently checked for an actual predeadline disconnect and absence of later upstream/response revival. New ready proof must match the selected exact source profile, configured feature tuple and optional ordered source feature rows. The helper does not invent a missing old error/closed-afterdeadline capture.

Current selection follows the mounted provider: `focusKind=molecular_profile` plus `focusId` takes priority over legacy `type`/`typeBaseline`; when the native reader supplies `profileId`, it must agree with that active URL key. This does not admit a source record or turn URL metadata into source proof.

DOM states: `held`, `pair_closed`, `rna_closed`, `non_cano`, `profile_switched_closed`, `pair_error`, `pair_ready`, `single_ready`. Same-source profile switching requires exact `profileIdBefore` and defaults to `profile_switched_closed`; switching outside CHOL can set `switchedState:"non_cano"`. Pair pending/failed/closed states withhold count tables, old pair proof and enabled pair exports. The held capture window must fall within the actual delay before disconnect. A cancellation/failure sibling phase needs a capture marked `afterDeadline:true`, whose entire observation window is later than every controlled canceled deadline. New precisely timed phase10+ artifacts are authoritative for strict replay. Old phase09 documents without clock brackets remain supplemental ordered native observations; no file mtime substitution or invented exact timestamp is permitted.

Native click completion does not itself flush React effects and socket aborts. Actual disconnect must be between action.startUTC and the first committed aftermath capture.endUTC, separately preserving the awaited interaction bracket. No arbitrary millisecond tolerance is used. Original `toolCaptureWindowUTC` embedded in every authoritative DOM is mandatory and must exactly match the sidecar. Cancellation phases require `action.evidencePath` to pin the original native action JSON and check its startUTC/endUTC; phase `evidencePaths` additionally pins original open/initiator records. A sidecar cannot supply exact brackets for a legacy unbracketed artifact.

Captured DOM files remain unchanged. `configPath` may point to the raw private schema snapshot or a recorded `{config:...}` wrapper. The helper reconstructs exactly the proxy's normalized rule object and matches `configSha256` per request; the pretty JSON file hash has a separate meaning. The final receipt pins every actually read manifest, log snapshot, config and DOM file. Partial trailing JSONL lines, reused request IDs from restarted proxy sessions and ownership overlap fail closed.

The final log may have unrelated request IDs; these remain explicitly unowned, never folded into pair request counts. Successful retry requires new IDs, original093/021 byte totals/hashes and a ready pair DOM proof with exactly two chunk receipts on origin3005. Wrong mode requires the actual original000 body served under021 and DOM pair rejection. Samechunk mode requires one pair000 request plus a distinct first-feature000 request, and independent pair/single ready DOM receipts.

The native reader's actual `singleJSON` field is used when present, otherwise its earlier `rnaJSON` field. No captured key is rewritten. For the pending-Pitx2 pair-close phase, list the newly owned021 single request separately from the new pair021/093 IDs, use the actual held-new-pair capture, then give the final capture twice as `pair_closed` and `single_ready`. Set `expectedFirstFeature:"Pitx2"` to bind the latter to its explicitly selected feature. Earlier tuple requests remain separate IDs and evidence; they cannot be merged with the new pair or single request. Ownership is a stated native isolated-operation inference, not a CDP/network-initiator claim.

Transport byte hashes describe bytes received by the proxy and handed to ServerResponse. They do not prove browser consumption or private source authenticity. Browser DOM proof is a separate native artifact. Export-file source replay remains delegated to source peer; this helper does not replay source RDS, original scientific partitions, downloads or admission counts.

No root/stage/source/config/server writes are authorized. Output is restricted to this helper's temp directory. During preparation do not execute `run()` against live data. At final replay, read a stable complete log snapshot after native capture completion and retain the snapshot hash/bytes alongside the source path.
